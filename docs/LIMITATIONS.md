## 原页版式路径的验收边界

[2026-10-27 案例](../cases/faithful-translation-20261027.md)及[运行记录](../artifacts/local-faithful-20261027/run.json)记录重新执行的 `faithful` 路径。翻译分组和最终导出显式选用相同模式，并使用 `strict` 质量策略；生成文件、局部 Copy-fit 返回成功或核验报告 `ok=true`，都不自动代表整页交付通过。具体覆盖量、视觉结论及阻断以该轮记录为准。

实际 DPI／物理页尺寸、中心与基线分段、局部边界合并、蓝底与线条区分、同一静态 TTF 的测量／嵌入／渲染，分别处理不同的几何和显示问题。它们不能纠正机器误译，也不能用缩小字体掩盖错误的单元格跨度。缺乏可信边界、与邻区冲突、容量不足或源字清理不完整时，需要继续记录失败或复核项，不能静默转单栏来满足“严格保留原页”的要求。

该路径保留原页背景，再加入原生定位文字；表格线条可见不等于存在原生 Word 表格，背景中的数字和图形也不是可编辑文字。`PASS`／`REVIEW`、部分型号及汇总串按现有保护策略保留为栅格内容，不能宣称全文汉化。原表数量 `2`、`1` 对应 OCR 单元格仍为空，背景能看到这两个数字不应计入识别成功或译文覆盖。

`Qty → 齐哥`、`ground truth → 地面真相` 等实际误译、`Not an OCR result` 对应说明遗漏，以及工程符号识别错误仍需单独报告。文字写入完整只针对保存的模型输出，不证明原文含义没有遗漏。字体身份一致也不能保证 OCR 推断的字号、标题层级和阅读顺序完全正确；Microsoft Word 内的交互编辑尚需独立验证。

公开核验的 `local_faithful` 入口或 `verify_translation.py --record artifacts/local-faithful-20261027/run.json` 仅检查冻结证据。完整渲染、翻译与恢复实现仍未公开，精选代码保持原有 8 个；不能仅凭公开包复现服务端全部处理。

## 2026-10-26 历史单栏重排的限制

[历史英译中案例](../cases/english-to-chinese-20261026.md)使用 Argos `translate-en_zh` 1.9，实际译文仍有 `Qty → 齐哥`、`ground truth → 地面真相`、`Turn bugs into test cases → 将虫子变成试验病例` 等错误，以及 `Not an OCR result` 对应说明遗漏。原样输出没有经过人工校对；不能因为模型返回中文或运行时没有报错，就称翻译正确。

该历史轮次的 PLOS 三页、表格一页通过当时限定的重叠、溢出与显示检查；111 条 PLOS 显示行、4 条表格正文及 19 个非空预测格均在 DOCX/PDF 找到。PLOS 改成 10.5 pt 单栏原生文字，图内文字变为段落，原双栏、蓝底与页数不保留。它不是 2026-10-27 原页版式路径的验收结论，旧产物和失败证据继续保留。字面匹配检查译后结果的保留情况，无法发现模型在生成译文时已遗漏的原文含义。人工语义校对、完整阅读顺序和 Word 编辑体验仍待完成。

## 工程字符仍会识别错误

自制表格有两处 `Ø → ∅`，即使识别置信度较高，转写仍然错误。21 个单元格中 19 个文字完全匹配，结构及跨度 21/21 匹配；结构正确不抵消文字错误。

上述是 2026-10-07 历史结果。2026-10-26 本地 CPU 路径的同一表格预测出 30 格，对照 21 格真值文字匹配 13/21、位置及跨度匹配 16/21，字符编辑为 24/203，5 个合并关系全部漏检。PLOS 页保存了 103 条块内文字行，但没有独立校对的全文准确率或阅读顺序验收。

评分保留 Unicode 字符差异，不将 `Ø、⌀、∅、Φ` 合并成同一个字符。不能通过全局替换、规则补写或候选池命中提高最终转写分数。待复核应单独报告，不能视作已经识别正确。

公差关联只组合实际观测到的文字和符号。几何关系不明确、上下偏差缺项或局部裁剪不完整时，需要保留失败或疑点；当前片段不解析形位公差图形、焊接符号或管线连接关系。

## DOCX 修复与视觉验收分别记录

**2026-10-26 首次 CPU 实测的两份 DOCX 视觉失败，原记录保持不变。** LibreOffice 7.4.7.2 与 Poppler 22.12.0 在独立断网容器中，将未修改的原始 DOCX 以 144 DPI 渲染。两份都输出一页：[PLOS 原始预览](../artifacts/local-20261026/plos/render/page-1.png)有大量正文重叠、断行，蓝色摘要背景只局部保留；[表格原始预览](../artifacts/local-20261026/merged-table/render/page-1.png)虽对应含有一个 `w:tbl` 的 DOCX，却未显示表格主体，页脚也重叠。

[后续 DOCX 修复记录](../cases/docx-export-fix-20261026.md)独立保存同一输入的新结果。最终重跑的两份一页 DOCX 通过限定的导出验收（`passed_for_export_targets`）：PLOS 原有叠行消除，原生表格主体可见，页脚不再重叠。PLOS 的 DOCX 与 PDF 均可匹配 103/103 条块内文字行，表格均可匹配 23/23 行及 19/19 个非空预测单元格；前后 OCR 文字和几何投影一致。

修复仅调整导出逻辑，不手工替换 OCR 文字或合并关系；原始 13/21 文字匹配、30 格预测及 5 处合并漏检仍需单独报告。表格能显示，不等于原文结构正确。PLOS 的字体、字号和间距与原文不同，蓝色背景只局部保留，图像区域仍存在，碎片化文字的完整阅读顺序尚未独立验收。这些结果不属于整页版式保真或完整可编辑交付通过。

内容核查统计保存的 OCR 行及预测单元格文字在 DOCX XML 和渲染 PDF 中是否出现。PLOS 旧预览虽然有 102/103 行可匹配，却仍大量叠行；因此字面匹配数不能取代逐页视觉检查。相同文字的子串匹配可能重复使用同一处文本，也不足以证明完整性、阅读顺序或实际编辑行为。

2026-10-07 的工程图 DOCX 有文字重叠，自制表格 DOCX 有文字缺失、边框不完整及标题／页脚重叠。保存的预览来自 LibreOffice 转 PDF 再渲染，见[首页对照](../README.md#输入和失败预览)。

Microsoft Word 未参与这些验证，不能推断它的实际表现。可读取 DOCX、存在原生表格、跨度 XML 正确或 Copy-fit 返回 `fits=True`，都不足以证明最终页面正确。每次修复需保存新的渲染，并分别记录使用的客户端、字体、版本与具体验收范围；文字不重叠和表格可见，也不等于整页版式、图像区域或可编辑交付全部通过。

## 识别、版面与文件格式不能互相代替

| 能力或产物 | 需要单独确认的证据 |
|---|---|
| OCR 文字 | 对照明确的参考文字评分；文本框数量和高置信度不代表识别正确 |
| 表格结构 | 比较行列、单元格跨度和文字；结构匹配不代表单元格内容正确 |
| 版面还原 | 查看真实导出文件的渲染，检查缺字、叠字、边界与顺序 |
| 可搜索 PDF | 确认导出 PDF 存在可检索的文字层；预览 PDF 或图片不是该能力证明 |
| 可编辑 Word | 检查导出对象及实际编辑行为；页背景图片不可作为文字或表格编辑 |

完整项目中重建 PDF 与叠加不可见文字层的可搜索 PDF 是不同路径。公开案例未验证的能力不由文件扩展名推断，也不把 DOCX 创建成功写成版式或编辑体验已验收。

## VLM 与训练边界

三个公开 VLM 文件只展示证据、几何和策略检查，不加载模型、不执行完整兜底流程。VLM 输出是候选；模型自报置信度、跨模型一致、LaTeX 可渲染都不能代替内容验真。

[第四轮记录](../cases/engineering-fallback-round4.md)明确保留当时尚未执行的新模型推理，不能使用论文的公式分数作为本项目的工程图成绩。是否需要微调仍需根据完整清晰裁剪的失败类型、可靠标签和独立验证集判断。

后续 20 张真实图纸已经用于开发或回归，不再作为独立验收集。工程参考尚未经过新增人工确认；关键符号 ≥99%、完整标注 ≥95% 是目标，不是已达到的成绩。模型生成的候选不能直接导出为工程训练真值。

## 数据与可复现范围

自制表格的输入及真值可以公开复算。DEXPI 的来源、原生文字提取与 OCR 输出分别保存，不混作同一种证据。其他真实工程图纸仅公开已审核的来源、哈希、派生分数和必要失败摘录，未确认再分发许可的原图及完整裁剪不随仓库提供。

因此，读者能够复算公开表格、运行算法测试并检查案例，但无法仅凭本仓库重跑所有历史模型实验。来源哈希和发布清单用于追溯及一致性检查，不是外部真实性签名。[来源与许可详情](../CASE_SOURCES.md)

## 运行范围

- Python 3.11+ 是设计目标；实际检查的版本、日期和范围见[验证记录](VALIDATION.md)。
- 默认离线核验和独立测试仅用标准库；真实 PDF 路由、样本生成和 HTTP 客户端各有可选依赖。
- Windows 的示例命令使用 `-X utf8`；字符显示还依赖终端字体。
- 新样本或复测报告写入尚不存在的独立输出位置；不覆盖冻结证据。
- HTTP 客户端需要已有兼容服务，仓库不提供一键启动服务或自动下载模型。
