# 已知限制与证据边界

[首页](../README.md) · [运行指南](GETTING_STARTED.md) · [评测口径](../EVALUATION.md) · [本次验证](VALIDATION.md)

本仓库提供可运行的精选算法和可检查的历史证据。它没有包含完整 OCR 服务、模型权重、训练流程或生产部署配置，也不保证任意文档都能正确识别或转换。

## 当前检查与历史实测不同

| 记录 | 可以说明什么 | 不能据此说明什么 |
|---|---|---|
| 当前独立测试与离线核验 | 公开片段的指定行为、保存证据的一致性 | 当前完整服务已重新 OCR，或所有生产功能已通过 |
| 2026-10-07 两个固定案例 | 当时环境、参数下的输出、逐格分数和串行延迟 | 总体准确率、并发能力、当前代码的性能 |
| 2026-10-08 后续工程图开发实验 | 已选区域的开发参考一致性与失败类型 | 独立人工验收、整页所有文字准确率 |
| 第四轮保存记录 | 当时本地验证、疑点路由和未执行项目 | GLM-OCR、MinerU、FormulaNet 已有本项目推理成绩 |

历史日期不能随文档整理变成新的测量日期。重复处理同一页可以观察耗时变化，但不会增加准确率样本数。远端 CI 的实际状态以对应运行记录为准。

## 工程字符仍会识别错误

自制表格有两处 `Ø → ∅`，即使识别置信度较高，转写仍然错误。21 个单元格中 19 个文字完全匹配，结构及跨度 21/21 匹配；结构正确不抵消文字错误。

评分保留 Unicode 字符差异，不将 `Ø、⌀、∅、Φ` 合并成同一个字符。不能通过全局替换、规则补写或候选池命中提高最终转写分数。待复核应单独报告，不能视作已经识别正确。

公差关联只组合实际观测到的文字和符号。几何关系不明确、上下偏差缺项或局部裁剪不完整时，需要保留失败或疑点；当前片段不解析形位公差图形、焊接符号或管线连接关系。

## DOCX 已生成，但视觉验收未通过

2026-10-07 的工程图 DOCX 有文字重叠，自制表格 DOCX 有文字缺失、边框不完整及标题／页脚重叠。保存的预览来自 LibreOffice 转 PDF 再渲染，见[首页对照](../README.md#输入和失败预览)。

Microsoft Word 未参与该次验证，不能推断它的实际表现。可读取 DOCX、存在原生表格、跨度 XML 正确或 Copy-fit 返回 `fits=True`，都不足以证明最终页面正确。后续修复需要重新渲染，并分别记录使用的客户端、字体和版本。

## VLM 与训练边界

三个公开 VLM 文件只展示证据、几何和策略检查，不加载模型、不执行完整兜底流程。VLM 输出是候选；模型自报置信度、跨模型一致、LaTeX 可渲染都不能代替内容验真。

[第四轮记录](../cases/engineering-fallback-round4.md)明确保留当时尚未执行的新模型推理，不能使用论文的公式分数作为本项目的工程图成绩。是否需要微调仍需根据完整清晰裁剪的失败类型、可靠标签和独立验证集判断。

后续 20 张真实图纸已经用于开发或回归，不再作为独立验收集。工程参考尚未经过新增人工确认；关键符号 ≥99%、完整标注 ≥95% 是目标，不是已达到的成绩。模型生成的候选不能直接导出为工程训练真值。

## 数据与可复现范围

自制表格的输入及真值可以公开复算。DEXPI 的来源、原生文字提取与 OCR 输出分别保存，不混作同一种证据。其他真实工程图纸仅公开已审核的来源、哈希、派生分数和必要失败摘录，未确认再分发许可的原图及完整裁剪不随仓库提供。

因此，读者能够复算公开表格、运行算法测试并检查案例，但无法仅凭本仓库重跑所有历史模型实验。来源哈希和发布清单用于追溯及一致性检查，不是外部真实性签名。[来源与许可详情](../CASE_SOURCES.md)

## 运行范围

- Python 3.11+ 是设计目标，本次本地检查使用 Python 3.12.14；具体检查见[验证记录](VALIDATION.md)。
- 默认离线核验和独立测试仅用标准库；真实 PDF 路由、样本生成和 HTTP 客户端各有可选依赖。
- Windows 的示例命令使用 `-X utf8`；字符显示还依赖终端字体。
- 新样本或复测报告写入尚不存在的独立输出位置；不覆盖冻结证据。
- HTTP 客户端需要已有兼容服务，仓库不提供一键启动服务或自动下载模型。
